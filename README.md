# Tibris × Digital Cube

Новая версия Telegram-бота: игровой Digital Cube и персональная арт-студия Tibris.
Исходный проект: [digital-cube](https://github.com/tibrisvolk-cloud/digital-cube). Это отдельный репозиторий и отдельная версия базы.

![Обложка студии](assets/main.png)

## Что умеет бот

- Digital Cube: загадки, задания на подписку/таймер/код, баланс pts, магазин, склад, ручная и автоматическая выдача.
- Студия: Classic, Light и Minecraft. Сохранены реальные рублёвые цены из прайса; примерные Stars/USD/USDT не опубликованы как утверждённые.
- Заказ: формат с ценой на кнопке → подробный фон → второй/третий персонаж → описание и референсы → итог и выбор оплаты → согласование → оплата → выдача. Свободный слот резервируется автоматически.
- Слоты отдельно у **каждой позиции**, а не общая очередь категории. Начальные три места на позицию можно закрывать, открывать и дополнять через админку.
- Профиль: баланс Cube, купоны, покупки, все заказы с пагинацией и ссылка на чат с художником.
- Купоны за баллы, отдельные арты за pts, текстовые промокоды с лимитом/сроком и одной активацией на пользователя. Один купон на заказ, без суммирования скидок.
- Фотографии и изображения файлами: обложки меню, карточки, загадки, товары, портфолио и QR-коды. Бот использует Telegram file_id, ссылки на картинки не требуются.
- Админка с кнопками: заказы по этапам, каталог и цены, слоты, оформление, способы оплаты, промокоды, Digital Cube и клиенты. Настройки заполняются по одному вопросу, команды необязательны.
- Изображение, подпись и кнопки меню отправляются одной карточкой. Очень длинный текст продолжается следующим сообщением из-за лимита подписи Telegram.

## Быстрый запуск

Python 3.11+; запускать из корня проекта. Python 3.12 используется в CI и Docker.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
# Заполните BOT_TOKEN и свой числовой ADMIN_ID в .env
.venv\Scripts\python -m studio
```

Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# Отредактируйте .env
.venv/bin/python -m studio
```

Создайте бота у BotFather. Администратор должен отправить ему `/start`, чтобы бот мог присылать заявки.
Для надёжной проверки подписок сделайте бота администратором соответствующих каналов.
`ARTIST_USERNAME` оставлен пустым: впишите его в окружении или выберите «Управление → Мои настройки → Telegram для связи».
После заполнения в профиле появится кнопка прямого перехода в ваш чат. Пока username не задан, работает передача сообщений через кнопку «Написать Tibris»; для ответа администратор нажимает «Ответить».

## Размещение на BotHost

На [странице создания бота](https://bothost.ru/create-bot.php) выберите Telegram и Python. Репозиторий: `https://github.com/tibrisvolk-cloud/tibris-cube-studio.git`, ветка `main`.
В дополнительных настройках укажите главный файл `main.py` и стандартную автоматически генерируемую сборку Python. Для этого варианта опция собственного Dockerfile должна быть выключена.
Токен указывается в поле Bot Token или переменной `BOT_TOKEN` в панели; файл `.env` на хостинг загружать не требуется.

Перед запуском добавьте переменные:

| Ключ | Значение |
|---|---|
| ADMIN_ID | Ваш числовой Telegram user ID, без @ |
| DB_PATH | /app/data/bot_data.db |
| ARTIST_NAME | Tibris |
| ARTIST_USERNAME | Ваш username без @; можно пока не добавлять |

BotHost автоматически устанавливает зависимости из `requirements.txt`. Путь `/app/data` выбран для сохранения базы при обновлениях из Git. При первом запуске бот создаст её сам. API-ключи оплат подключайте отдельно после запуска основного бота.
Сохраните настройки, выполните деплой и смотрите runtime-логи. Затем отправьте `/start` боту из своего администраторского аккаунта.
Если появляется Conflict от getUpdates, остановите второй процесс с тем же токеном. При ошибке записи базы проверьте доступность папки `/app/data` на хостинге.

Источники: [быстрый старт BotHost](https://bothost.ru/docs/getting-started), [главный файл](https://bothost.ru/docs/main-file-entrypoint), [переменные окружения](https://bothost.ru/docs/environment-variables), [постоянное хранение базы](https://bothost.ru/docs/database-storage).

### Docker

```sh
docker compose up -d --build
```

База хранится в отдельном volume `bot-data`. Не запускайте два процесса бота с одним токеном одновременно.
База, ключи, референсы и платежные данные не должны попадать в Git. `.gitignore` исключает `.env` и базы.

## Первичная настройка художника

Отправьте `/start` → «Управление» или `/admin`. Для обычной работы команды не нужны.

1. **Мои настройки** — имя, Telegram для связи, ссылка на портфолио, открытие/закрытие заявок.
2. **Картинки и тексты** — выберите раздел и пришлите текст или изображение. Примеры работ можно добавлять и удалять. Сгенерированные обложки являются оформлением, а не портфолио Tibris.
3. **Каталог и цены** — цена ₽/Stars/баллов, описание, картинка, скрытие позиции. Здесь же настраиваются подробный фон (по умолчанию 400 ₽) и доплата за второго/третьего персонажа (по умолчанию 100% базовой цены каждый).
4. **Слоты** — отдельные места для каждой позиции; закрывайте, открывайте или добавляйте их кнопками. Клиенту выбирать технический номер слота не нужно.
5. **Оплата** — СБП, ЮMoney, Hipolink, TON или USDT: название кнопки, подтверждение, реквизиты и курс в рублях за единицу. Секретные ключи автоматической оплаты добавляются только в окружении хостинга. Без них автоматический способ клиенту не предлагается.
6. **Промокоды** — текст, процент, лимит, срок. В каждом сообщении один вопрос; кнопка «Пропустить» убирает ограничение. Уже выданные купоны сохраняются после закрытия кода.
7. **Digital Cube** — пошаговое создание загадок, заданий, товаров и бонусов, скрытие записей и ручная выдача.
8. **Клиенты** — ответ текстом/файлом, начисление и списание баллов.

Временный резерв черновика действует 30 минут и продлевается на каждом шаге. Кнопка отмены возвращает в меню и освобождает место.
Пример расчёта: фулл 600 ₽ + подробный фон 400 ₽ + второй персонаж 600 ₽ = **1600 ₽**. Третий персонаж добавит ещё 600 ₽. Купон применяется ко всему итогу.
Базовые цены и доплаты фиксируются в черновике, поэтому изменение прайса не меняет расчёт уже заполняемой заявки. Новая заявка использует актуальные цены.

### SKU и реальные базовые цены

| SKU | Формат | ₽ |
|---|---|---:|
| classic_head | Classic · хэд | 180 |
| classic_half | Classic · по пояс | 250 |
| classic_sticker | Classic · стикер | 70 |
| classic_full | Classic · фулл | 600 |
| light_icon | Light · иконка | 150 |
| light_chibi | Light · чиби | 300 |
| mc_skin | Minecraft · скин | 300 |
| mc_totem | Minecraft · 3D тотем | 120 |
| mc_animal | Minecraft · лиса / волк | 180 |

В Classic и Light доступны фон и дополнительные персонажи; для Minecraft эти шаги пропускаются. В описании чиби указана возможность версии без фона.
YCH, лого, отдельный фон Light и 4D скин убраны. Обновление скрывает старые позиции, сохраняя их заказы, оплаты и файлы.
Незавершённые черновики старой формы при первом обновлении сбрасываются вместе с временным резервом; уже отправленные заявки сохраняются.

## Согласование и выдача

В «Заказах» выберите этап: новые, ждут оплаты, оплачены, в работе либо весь архив. В карточке доступны референсы и ответ клиенту.
Для новой заявки нажмите **«Принять и указать срок»**: бот использует рассчитанную стоимость и попросит срок/условия. Кнопка **«Изменить цену и условия»** позволяет предложить другую стоимость до скидки.
Клиент после согласования выбирает платёжный способ. Рубли и установленные вами курсы пересчитываются автоматически, скидка применяется один раз. Stars предлагаются только при установленной цене; для заказа с подробным фоном нужна также цена фона в Stars. За баллы предлагается только базовый арт без доплат и купона.

Чек клиента не подтверждает оплату. Для ручного перевода используйте **«Подтвердить поступление»** и укажите уникальный номер операции после сверки выписки. Для автоматического счёта доступна проверка по API.
После оплаты: **«Начать работу» → «Выдать готовую работу» → отправить файл/фото**. Статус «Выдан» сохраняется после успешной отправки. Клиент может скачать результат повторно, обычный слот освобождается.
В карточке есть подтверждаемый возврат Stars/баллов. Внешний возврат сначала выполняется вами в сервисе, затем записывается его номер. Отдельная кнопка позволяет отменить заказ с открытым внешним счётом; поздний платёж попадёт на ручную проверку.

Команды из `/adminhelp` остаются дополнительными сокращениями, но все основные действия доступны в меню.

## Оплаты

| Способ | Подтверждение | Что нужно |
|---|---|---|
| Telegram Stars | Автоматическое | BOT_TOKEN, согласованный прайс XTR |
| TON / USDT через Crypto Pay | Автоматическое через API | Аккаунт/приложение Crypto Pay и API token |
| Рубли в личный кошелёк ЮMoney | Автоматическое через API | Кошелёк и OAuth token только на чтение |
| СБП на личную карту | Ручное | Ваши реквизиты, проверка поступления в банке |
| Hipolink | Ручное | Ваш аккаунт, ссылка на оплату и проверка кабинета |
| Прямой перевод криптовалюты | Ручное | Ваши реквизиты с точной сетью |

ЮKassa и статус самозанятого не являются техническими зависимостями этого проекта. Все внешние способы изначально не настроены.
Инструкции, комиссии, ограничения Telegram и варианты получения денег из России: [PAYMENTS.md](docs/PAYMENTS.md).

Для ручного способа:

```text
/method sbp RUB ВАШИ_РЕКВИЗИТЫ
/method hipolink USD ВАША_ССЫЛКА
/method gram GRAM ВАШ_АДРЕС_И_СЕТЬ
/method usdt USDT ВАШ_АДРЕС_И_СЕТЬ
/image payment:sbp
# затем QR-код изображением
/offer ID способ сумма_в_его_валюте базовая_цена_руб условия_и_срок
/markpaid ID уникальный_номер_операции
```

`/markpaid` используется **после** проверки фактического поступления. Чек клиента сам по себе не помечает заказ оплаченным.
Для меню задайте свой курс через «Управление → Оплата». Цена USD/USDT/TON рассчитывается из согласованного рублёвого итога и этого курса, с округлением вверх. Команда `/offer` остаётся способом вручную предложить конкретную сумму.

Для автоматического способа:

```text
/methodauto ton TON cryptopay
/methodauto usdt USDT cryptopay
/methodauto rub RUB yoomoney
/offer ID способ сумма_в_его_валюте базовая_цена_руб условия_и_срок
```

Добавьте соответствующие ключи в `.env` и перезапустите бота. Без ключей платёжная ссылка не создаётся.
Проверка выполняется раз в 30 секунд **плюс время обхода открытых счетов**, а также по кнопке «Проверить сейчас». Публичный HTTPS endpoint для webhook не требуется.
Подтверждаются только финальные операции нужного счёта/кошелька, валюты, суммы и уникальной метки заявки. Ключ ЮMoney не должен иметь права исходящих переводов.
Комиссия карточного перевода ЮMoney показывается клиенту до открытия ссылки: рублёвое предложение считается суммой к получению художником. Проверьте `YOOMONEY_CARD_FEE` по своему тарифу.
`/autopaystatus` показывает счета и проблемные операции. `/voidinvoice ID` отменяет заявку с открытой внешней ссылкой: позднее поступление отслеживается и уходит на ручную проверку/возврат, без повторного занятия слота.

## Перенос Digital Cube

Сначала остановите старый бот и сохраните его базу. Новый код **не изменяет** исходный файл:

```sh
python -m studio.migrate /path/to/old/bot_data.db data/bot_data.db --legacy-utc-offset 3
```

Число `3` подходит только если старый сервер записывал локальное московское время. Укажите реальное смещение старого сервера; для UTC — `0`.
Файл назначения должен быть новым. Перенос сохраняет пользователей, балансы, загадки, задания, попытки и покупки; миграции каждой колонки независимы и повторяемы.
Журнал `ledger` учитывает новые движения, восстановить отсутствующие исторические движения нельзя.
Telegram file_id привязан к боту: при новом боте старые изображения/файлы потребуется загрузить заново. Пользователи также должны нажать `/start` в новом боте, прежде чем он сможет им написать.

## Проверка и структура

```sh
python -m pip install -e '.[dev]'
ruff check .
pytest -q
```

- `studio/store.py` — баланс, лимиты, слоты, скидки, заказы и транзакции SQLite.
- `studio/bot.py` — Telegram-карточки, платежи и единый роутер сообщений.
- `studio/order_ui.py` и `studio/ordering.py` — конструктор заказа, расчёт доплат и выбор оплаты.
- `studio/admin_ui.py` — кнопки управления и пошаговые формы.
- `studio/autopay.py` — подтверждение через API Crypto Pay / ЮMoney.
- `studio/catalog.py` — стартовые цены и тексты.
- `studio/migrate.py` — перенос копии старой базы.
- `assets/` — четыре декоративные AI-обложки и сохранённые промпты.
- `tests/` — регрессии старых багов, гонки лимитов/слотов, купоны, сохранение старых заказов, промокоды, конструктор, админские формы, права и платежи.

Провайдеры проверены на моделируемых ответах официальных API. Реальные платежи, тестовая сеть Crypto Pay и доставка живому Telegram-боту требуют ваших аккаунтов и ключей и здесь не выполнялись.
