# Подключение и получение оплат

Проверено по официальной документации 14 октября 2026 года. Код поддерживает несколько способов; наличие технической интеграции не означает одобрения способа платформой или гарантии доступности аккаунта.

## Telegram Stars

После согласования создаётся счёт XTR. Проверяются пользователь, сумма, валюта и актуальность предложения. Обработка повторного события идемпотентна; лишний второй платёж сохраняется и возвращается. `/paysupport` работает через связь с Tibris.
Цена Stars не равна рублёвому прайсу автоматически. Размеры в первоначальном примере не использованы как утверждённый тариф.

Источник: [Bot Payments for Digital Goods](https://core.telegram.org/bots/payments-stars).

Вывод вознаграждения выполняется владельцем через Fragment. Это не банковский USD-платёж: доступность вывода зависит от Fragment и региона; Telegram не обещает альтернативную компенсацию при недоступности.
Источник: [раздел 6.2.4 правил разработчиков](https://telegram.org/tos/bot-developers#6-2-4-rewards-for-stars).

## Crypto Pay · автоматический TON/USDT

1. Самостоятельно заведите аккаунт Crypto Bot и приложение Crypto Pay. Для разработки используйте CryptoTestnetBot.
2. Добавьте API token в `CRYPTO_PAY_TOKEN`; для тестовой сети установите `CRYPTO_PAY_TESTNET=1`.
3. Не включайте право исходящих переводов: адаптер создаёт счёт и читает статус, не выполняет выводы.
4. В боте: `/methodauto ton TON cryptopay` и/или `/methodauto usdt USDT cryptopay`.
5. После заявки используйте `/offer ID ton сумма базовая_цена_руб условия`.

API создаёт счёт на 1 час, с уникальной скрытой меткой заказа. При неопределённом результате запроса создания бот ищет уже созданный счёт по метке вместо слепого повторного создания. Если восстановить не удаётся — состояние `uncertain`, нужен осмотр администратором.
По официальному API код нативного актива сейчас `TON`; подпись кнопки/способа может быть `GRAM`, но код не предполагает без проверки, что это отдельный взаимозаменяемый токен. Поддержка `GRAM` в локальной настройке отображения сопоставляется с API-активом TON, что явно учитывается при проверке.
Вывод из Crypto Pay и получение рублей выполняются вами в поддерживаемых сервисом способах; бот не обещает банковского долларового вывода и не проводит обмен.

Источник: [официальный Crypto Pay API](https://help.send.tg/en/articles/10279948-crypto-pay-api).

## ЮMoney · автоматические рубли в личный кошелёк

Это API кошелька ЮMoney, без ЮKassa. Потребуются кошелёк, доступ к API и соблюдение условий сервиса для вашего использования.

1. Получите OAuth token с **только** `account-info operation-history operation-details`. Не добавляйте `payment`, `payment-shop` или права переводов.
2. Запишите номер кошелька в `YOOMONEY_WALLET`, токен в `YOOMONEY_TOKEN`.
3. В боте: `/methodauto rub RUB yoomoney`.
4. Согласуйте предложение `/offer ID rub сумма_к_получению базовая_цена_руб условия`.

Бот сверяет владельца токена с номером кошелька. Платёжная форма карточного перевода получает уникальный `label`. API истории должен вернуть входящую финальную принятую операцию по этой метке и сумму, достаточную для предложения. Скриншот клиента не участвует в автоматическом подтверждении.

В официальной документации карточная комиссия формы `AC` — 3% с получателя от суммы списания. Адаптер рассчитывает сумму к оплате так, чтобы после этой комиссии у вас была согласованная сумма. Например, к получению 180 ₽ → по карте 185,57 ₽. Клиент видит эту сумму перед переходом. `YOOMONEY_CARD_FEE` настраивается по фактическому тарифу.
Обычный перевод по номеру кошелька/телефона, без метки созданной формы, не считается оплатой автоматически. СБП на личную банковскую карту также не подменяется этой интеграцией.

Источники: [форма и комиссии](https://yoomoney.ru/docs/payment-buttons/using-api/forms), [история операций](https://yoomoney.ru/docs/wallet/user-account/operation-history), [права токена](https://yoomoney.ru/docs/wallet/using-api/authorization/protocol-rights).

## СБП на личную карту

`/method sbp RUB ваши_реквизиты`, при необходимости `/image payment:sbp` и изображение QR.
Вручную проверяйте поступление в банке. `/markpaid` записывает уникальный номер реально проверенной операции. Без официального доступа к истории банка универсальное автоматическое подтверждение этого варианта не реализовано.
ЮKassa намеренно не является зависимостью проекта и не нужна для запуска выбранной версии.

## Hipolink и иностранные заказчики

Для заказчиков с зарубежными картами можно проверить Hipolink как отдельную внешнюю платформу для услуг/контента: его официальные условия для СНГ описывают валютные переводы с конвертацией в выбранную валюту и вывод на карты в RUB. Это позволяет обсуждать цену в USD, получая выплату в рублях; получение именно долларов на российский счёт этим не гарантируется.

По условиям для СНГ от 30 июля 2026 года: комиссия карточных платежей 11,7%, вывод на рублёвые карты 1,9% + 20 ₽; при валютной конвертации возможен вычет до 6% от справочного курса. Условия выплат содержат лимиты и право задержки. Они важнее рекламного блока с округлённой комиссией. Проверьте доступность вашей карты и небольшой реальный вывод прежде, чем обещать этот метод всем клиентам.

В проекте: `/method hipolink USD ваша_ссылка`, затем согласованная цена `/offer`. Подтверждение ручное через кабинет и `/markpaid`. Публичный официальный API заказов/платежей Hipolink в проверенных материалах не найден; автоподтверждение для него не выдумано. Если поддержка предоставит документированный API/webhook, можно добавить адаптер.

Источники: [платформа Hipolink](https://hipolink.net/ru), [действующие условия для СНГ](https://hipolink.net/en/app/payment-term-cis).

## Правила Telegram: разные ограничения

Существование у других ботов меню СБП/криптовалют — свидетельство технической возможности, а не подтверждение правил для данного товара. В официальных текстах:

- [Раздел 6.2](https://telegram.org/tos/bot-developers#6-2-digital-goods-and-services) требует Stars для цифровых товаров/услуг через TPA и описывает последствия альтернативных способов.
- [Раздел 7](https://telegram.org/tos/bot-developers#7-blockchain-integration) отдельно ограничивает блокчейн-интеграции Mini Apps сетью TON. Это не отменяет раздел 6.2.
- [FAQ платежей](https://core.telegram.org/bots/payments-stars) отдельно отвечает на использование криптовалюты вместо Stars и внешней витрины для продажи внутри Telegram.

По запросу владельца подготовлены технические внешние способы с отдельными настройками. Они не заявлены как автоматически соответствующие этим правилам. Stars — встроенная официальная оплата цифровых заказов. Внешний Hipolink можно использовать для самостоятельных продаж на его площадке; наличие площадки не делает любой checkout внутри Telegram исключением из правил.
Регистрация бота/кошелька не заменяет проверку условий сервиса и правил учёта дохода для вашей ситуации. Проект не регистрирует самозанятость, ИП, платёжные аккаунты или финансовые договоры.

## Ключи, подтверждение и возврат

Все настоящие ключи задавайте в `.env` на сервере, не отправляйте в чат и не коммитьте.
Не запускайте реальные оплаты до проверки тестовой сетью/минимальной суммой с собственными аккаунтами. Сейчас нет живых подключений: тесты моделируют ответы API.
Возврат Stars автоматизирован командой администратора. Crypto Pay/ЮMoney используются без прав вывода, поэтому внешние возвраты выполняются вами вручную и затем записываются `/refundexternal`.
`/voidinvoice` освобождает слот отменённой заявки; действующая внешняя ссылка может технически остаться у клиента. Поступление по ней переводится в журнал ручной проверки, а не в новый оплаченный заказ. Такие операции видны в `/autopaystatus` и требуют реального внешнего возврата/согласования с клиентом.
